# Token Atlas · 模型价格观察站

公开、无需 API Key 的静态模型价格计算器。默认输入与输出各 **100,000,000 token**，缓存命中率 **90%**；可切换到一百万。每天抓取公开价格，保留不可覆盖的历史快照与原始证据。

- 页面：https://100apps.github.io/token-price-observatory/
- 数据：[latest.json](data/latest.json)
- 快照索引：[history/index.json](data/history/index.json)
- 自动任务：[Daily prices and GitHub Pages](https://github.com/100apps/token-price-observatory/actions/workflows/daily.yml)

## 功能

1. 输入、输出、缓存命中率计算；平台/模型搜索、数据来源筛选、价格排序、按平台分组展开报价详情。
2. 相同模型 ID 的跨平台候选比价，保留地区、模式、上下文和服务等级差异；不宣称所有候选具备相同服务质量。
3. 逐报价的输入、缓存、输出历史折线和快照下载。默认最近 30 次，可选 90 次或全部；只展示真实采集历史。
4. 每行官方链接、数据来源类型、采集时间、旧数据状态、原始证据与抓取失败信息。
5. 默认 CNY 人民币显示，可切换 USD；使用每日抓取的 ECB 参考交叉汇率，支持手动指定。

**覆盖边界：** 这不是所有平台所有型号的全量已核验价格库；当前有部分官方直采及明确标识的社区补充。动态页面、登录墙、复杂促销和未识别结构会保留证据并标记未解析，不以硬编码旧价伪装实时价格。

## 计费口径

所有结构化单价都是原始币种的 **每百万 token**：

```text
(inputTokens × ((1 − hitRate) × inputPrice + hitRate × cacheReadPrice)
 + outputTokens × outputPrice) / 1,000,000
```

- 缓存价未知时按普通输入价估算，并显示提示；`0` 和未知值 `null` 严格区分。
- 三项输入只能估算 token 消耗成本。缓存写入、存储、工具、搜索、图片、音频、视频、税费、最低消费不在总额中，相关报价条件留在详情和官方证据。
- 累计用量不等于单次上下文。不会拿一亿累计 token 自动套进单次上下文的最高阶梯，用户应按实际单次请求选择对应报价行。
- 忙闲时段按官方表拆成独立报价，不按浏览器当前时钟替用户猜测使用分布。DeepSeek 的时区和节假日规则保留官方文字。
- 同模型候选仅以末段模型 ID 精确匹配，不合并版本别名。不同量化、地区、SLA、服务等级、供应商路由必须自行核对。
- 官方若改变页面结构，解析不足会告警；抓取失败保留上次成功值并标记 `stale`，不改变其原始成功观测时间。

## 每日工作流

GitHub Actions 在 **每天 02:23 UTC / 北京时间 10:23** 调度，也支持手动 `workflow_dispatch`。GitHub 定时任务可能延迟，公共仓库长期无活动可能暂停调度，不能保证分钟级时效。

流程：安装固定版本解析依赖 → 单元测试 → 并行抓取公开来源（超时重试） → 规范化并验证非负有限单价 → 保存证据与快照 → 原子更新 latest → 提交数据 → 上传静态文件并部署 Pages。推送代码只测试和部署，不重复采集。

```text
data/latest.json                         # 前端唯一当前价格入口
 data/history/<UTC timestamp>.json.gz     # 每次采集完整快照；早期 .json 也兼容
 data/history/index.json                  # 按新到旧的文件列表
 data/raw/<hash-prefix>/<sha256>.*.gz      # 原始字节 gzip，无变化不重复保存
```

原始证据 SHA-256 是解压后的字节摘要。下载 `.gz` 后可用 `gzip -dc file.json.gz` 或 Python `gzip.open` 读取。网页通过浏览器 `DecompressionStream` 读取压缩历史，需要较新的浏览器。快照不覆盖旧文件；代码解析升级可能改变字段/报价拆分，比较时须核对条件。

所有采集失败时不会覆盖已有 `latest.json`。部分失败在 Actions 中显示 warning，网站“数据来源”标记失败并保留原有报价。报价非结构化成功来源显示“已归档 · 未自动解析”。

## 本地运行与验证

Python 3.12+、Node.js 22+：

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python scripts/collect.py
python -m unittest discover -s tests -v
node --test tests/calc.test.mjs
python -m http.server 8000
```

打开 `http://localhost:8000`。没有构建步骤、模型调用费用或外部付费爬取服务。

## GitHub Pages 配置

在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。Actions 需要 `contents: write`、`pages: write`、`id-token: write`。首次启用后可在 Actions 页面手动运行工作流。组织若禁止工作流写仓库或部署，需要仓库管理员调整策略。

归档会随历史增长，gzip 与内容去重减少空间占用；长期使用仍需关注 GitHub 仓库及 Pages 配额，必要时迁移旧证据到独立对象存储，并保留快照链接。

## 扩展解析器

添加来源 → 写明确单位、币种和条件的解析器 → 添加独立价格样例测试 → 加入采集器解析列表。不要把未知缓存成本填成零，不要把旧路径返回的导航页当成新价格，不要把折扣系数当作绝对单价。为每条报价保留官方来源与观测时间。

## 准确性校验与分享（v1.1）

- 默认只对**过去 48 小时内、抓取成功的官方直采报价**排名。社区目录、抓取失败回退和异常隔离报价，可在“全部报价”查看，默认不推荐。
- 校验币种、有限非负单价、重复 ID 冲突；报价数量下降超过 30% 时整批拒收。任一单价变化超过 50% 或由零变收费/反向变化时，仅隔离相应报价、保留旧观测时间，其他模型继续更新。候选原文仍按 SHA-256 存档。“数据来源”提供复核告警。
- 缺少缓存单价仍会显示保守估算，不能宣称是准确账单；工具、缓存写入、税费等依旧不包含在 token 估算里。
- 百炼报价 ID 改为由模型与计费条件生成，不随价格改变；章节层级重新解析，防止上一地区标题串入本行。早期历史保留原有 ID，不推断合并不同地区的旧记录。
- 官方抓取样例固定在 `tests/fixtures/`，以独立写定的金额检查美元/人民币、百万 token 换算、缓存和忙闲分档。`sources.json` 的 SHA-256 指向原始完整文档，fixture 可能只摘录其中表格并补充编码元信息。
- 异常是真调价还是页面结构改变，需要维护者点开官方文档复核；核对后可运行 `python scripts/collect.py --accept-source PROVIDER=SHA256`。只批准完全匹配该摘要的当前文档，不绕过字段/重复冲突校验；下次抓取自动恢复常规门槛。若文档摘要已变化，会拒绝批准。审核记录写入快照的 `sources.reviewed_sha256`。
- 参数变化自动以 `history.replaceState` 同步 URL。支持 input、output、cache（百分数）、currency、fx、平台、搜索、排序、数据可信度、当前视图和历史选择。点击“复制分享链接”，打开可恢复同一组参数。非法参数回退默认值；零用量与 0% 缓存有效。
- 分享的是**计算参数**，报价采用打开时的最新快照，故以后再打开可能得到不同费用；快照本身仍可从历史页面下载。

这些门槛能发现常见单位错误、结构变化和异常调价，但不能从数学上保证厂商页面或解析器永远正确。最终账单仍取决于所选区域、模式、服务等级及官方计费规则。

## 更新失败恢复（v1.2）

Pages 已配置为 GitHub Actions 部署并强制 HTTPS。主任务每天 02:23 UTC（北京时间 10:23）；06:23 UTC（北京时间 14:23）的备用检查，仅在当天尚未成功更新或仍有来源失败时重新采集。日常仍是一份成功主快照；失败重试可能产生额外真实快照。

- 每个来源最多三次请求，使用 2 秒、8 秒退避和 45 秒请求超时。采集与部署均设置任务总超时。
- 一部分价格源失败：成功来源照常更新，对应失败来源的旧报价保留原观测时间并标为旧数据。
- 没有任何新鲜官方报价：**不修改 latest.json、不推进价格成功时间**。失败尝试记录在 `data/attempts/`，健康状态写在独立的 `data/health.json`。
- 意外异常：`scripts/refresh.py` 回滚本次不完整的价格指针与历史索引，记录明确的失败健康状态。剩余原始证据仍可用于诊断。
- 所有 JSON 指针用同目录临时文件原子替换；先保存快照与索引，再发布 latest。发布前验证文件、历史可解压性、ID 与非负有限价格。构建/验证/部署失败不会替换此前正常工作的 Pages 部署。
- 并发更新：工作流串行；如果开发者同时推送导致数据提交被拒，会保留本轮原始证据和历史，拉取最新代码后重新采集、重新提交，最多重试三次。不会通过强推覆盖别人的提交。重置仅允许在临时 Actions checkout 中运行。
- 每次更新将恢复数据保留为 Actions artifact，保存 14 天；提交失败也能下载恢复。
- 页面显示最近尝试、最后成功时间以及部分/全部失败状态；健康状态每分钟刷新，超过 48 小时的官方报价自动退出默认排名。
- 有来源失败时，先部署仍可用的数据和失败说明，再将工作流标记失败，便于 GitHub Actions 通知机制报告异常；隔离待复核报价用 warning 和页面说明表示。邮件等通知是否送达仍取决于仓库订阅和个人通知设置。

`python -m unittest discover -s tests -v` 覆盖所有源失败不覆盖旧价、部分成功、写索引失败、意外异常回滚、备用任务跳过/重试，以及临时 Git 仓库中的真实并发 push 冲突恢复。

GitHub 的定时任务可能延迟或因长期不活跃暂停；单靠仓库内的备用 cron 无法覆盖 GitHub Actions 整个平台停机或调度完全停止。健康时间与数据过期提示用于暴露这种情况，不宣称每日更新有外部 SLA。

恢复 artifact 是辅助备份：上传额度不足或服务故障会告警，但不会阻止正常数据提交与部署；原始证据仍随 Git 提交保留。当前价格和历史索引按 no-store 请求，减少浏览器缓存造成的旧价展示。


## 人民币默认显示与每日汇率（v1.3）

默认显示 CNY 人民币。每日价格任务同时读取 [ECB 官方每日 XML](https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml)，用**同一公布日的 CNY/EUR ÷ USD/EUR**计算 CNY/USD，保留 Decimal 原始基准值及交叉汇率，避免把报价方向用反。它是欧洲央行参考汇率，不等于银行卡、支付平台的实际结算汇率。

- `data/fx/latest.json`：当前参考汇率，包含公布日 `rate_date`、抓取时间 `observed_at`、来源、原始 XML 摘要及是否为失败回退。
- `data/fx/history/<采集时间>.json` 与 `index.json`：每次成功抓取的历史快照，周末重复同一公布日也保留真实抓取记录；网站“数据来源”显示最近 30 次及完整索引下载。
- `data/fx/attempts/`：失败尝试。汇率源失败会触发既有备用任务、健康提示及 Actions 失败信号。
- 每份模型价格历史快照的 `exchange_rate` 字段同时保留当次汇率。独立汇率采集即使模型源更新失败仍可保留，不虚构模型价格更新时间。
- 请求超时重试三次；无效数值、重复币种、未来日期、超过 7 天的公布日、日期倒退或汇率单次变化超过 10% 均拒收并保留证据。失败沿用上次成功值并标注旧汇率，不改原成功日期；首次抓取失败时不填入假设的 7.2，更不显示成免费。
- 周末/节假日通常没有新的 ECB 公布值，页面显示最近实际公布日。用户可以手动编辑或点击“使用最新汇率”恢复自动模式。
- 分享 URL 的 `fxMode=auto` 使用打开时最新参考汇率；`fxMode=manual&fx=...` 固定手动值。旧分享链接中仅有 `fx` 参数时，按手动值兼容；显式 USD 链接仍显示美元。新链接默认人民币。


## 平台与主流模型浏览（v1.4）

价格页改为“平台 → 模型 → 计费条件”三级展开，默认打开百炼，其余平台折叠。每个平台先显示最多 6 个主流推荐；同模型的地区、阶梯、忙闲时段等报价合并进一个模型入口，完整条件仍逐条保留，不拿某个低价条件代表所有用量。入口显示不同条件下的费用估算范围。

推荐名单在 `catalog.mjs`，维护日期 2026-11-07：按常用通用、推理、代码系列及近期主力版本精选，**不是实时热度或调用量排行**。当前抓取的公开价格目录没有统一可比较的跨平台调用量，故不虚构使用数据。维护者应定期复核名单；新出现但尚未选入的型号仍会照常抓取，可搜索或查看全部。没有匹配推荐时显示空状态，不用随机或免费的长尾模型凑数。

“再显示 6 个推荐”按平台独立展开；“查看该平台全部”才显示历史/长尾目录。搜索会查完整目录，便于明确查找某个旧型号。排序在平台内部应用，平台、模型展开状态及全部目录选择保存在分享 URL 中。默认的官方来源与过期排除规则保持适用，切换报价来源可查看仅有社区价格的平台。

## 百炼活动价与默认展开（v1.5）

用户指定的百炼价格依据为 [百炼北京模型市场](https://bailian.console.aliyun.com/cn-beijing/model/market)。每日任务改为读取该市场自身使用的只读目录接口，并保留响应证据；帮助文档另行归档作参考，**不再用文档标价替代活动价**。

2026-11-08 的实测：市场入口返回动态页面，其目录接口返回 HTTP 200 + `ConsoleNeedLogin` / `请登录`，并没有返回可核验的活动报价。当前没有登录会话，也没有公开优惠规则来源，因此不能声称百炼的活动价已采集成功。

为防止错误计算：旧百炼文档报价仍作为历史证据保留，但当前快照标记 `calculation_blocked=true`、`pricing_basis=unverified_list_price`。计算函数、所有来源筛选、默认推荐和跨平台比较均排除这些记录；页面直接显示“活动价待核验”并链接百炼控制台。定时任务继续探测市场可用性并记录失败，不尝试绕过登录，也不把未知返回字段或任意折扣数字当作实付价。

**尚未解决的依赖：** 需要可合法持续访问、包含适用地区/模型、输入输出/缓存单价、优惠期限、资格及套餐/领券条件的可靠百炼活动来源，才能实现百炼的每日活动价计算。当前市场解析器对未核验的数据结构拒收；接入成功样例并核对折扣含义前，不能自动放开。仅有“低至几折”的营销横幅不能当作所有请求都适用的折扣。

显示调整：默认打开 DeepSeek、OpenAI、Anthropic 等主流平台。各平台前 3 个推荐模型的价格默认展开，每个模型先展示 3 条地区/模式/时段条件，额外条件按需查看。非推荐型号继续折叠；用户手动收起的状态会保存在分享 URL 的 `closedModels` 中，不会因重新计算自动弹开。
